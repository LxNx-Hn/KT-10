## 1. 증상과 원인

바다에 가까운 경로에서 도보 경사가 `unavailable`로 나왔다. 계획서의 진단이
코드와 정확히 일치함을 확인했다.

```python
# 수정 전 ai/features/elevation.py
values = [ (y0,x0), (y0,x0+1), (y0+1,x0), (y0+1,x0+1) ]   # bilinear 4칸
if any(nodata 또는 non-finite for value in values):
    return None      # ← for 루프 밖으로 나간다
```

두 가지가 겹친다.

1. **격자가 90m라 해안에서 90m 안쪽이면 4칸 중 하나는 바다다.** 실제 보행로는
   멀쩡히 육지인데 걸린다.
2. **`return None`이 루프 밖으로 나가 표본 하나의 실패가 경로 전체를 버린다.**
   1km 중 90m만 해안에 닿아도 전부 `unavailable`이 된다.

### 착수 전 측정

번들 DEM `ai/data/precomputed/busan_dem_clipped_90m.tif` (546×627, 90m, EPSG:5179)

| 항목 | 값 |
| --- | --- |
| nodata 칸 | 247,934 / 342,342 = **72.4%** |
| 유효 고도 범위 | −7.3 ~ 776.1 m |

bilinear가 한 번에 읽는 2×2 창 기준 분포

| 유효 칸 수 | 창 수 | 비율 | 의미 |
| --- | --- | --- | --- |
| 0칸 | 244,079 | 71.5% | 바다·시계 밖. A안으로 못 살림 |
| 1~3칸 | 5,278 | 1.6% | **A안이 살릴 수 있는 해안 경계대** |
| 4칸 | 91,813 | 26.9% | 현재 성공하는 유일한 경우 |

실제 부산 해안 좌표로 확인한 결과 **A안만으로는 절반 정도만 복구**됐다.
표본 하나라도 0칸이면 여전히 경로 전체가 실패했기 때문이다. 이 측정 결과에
따라 계획서가 "A만으로 부족할 때" 조건으로 남겨둔 B안까지 함께 적용했다.

## 2. 적용한 수정

### A. 유효한 이웃만으로 재정규화 보간

`_regional_dem_elevations()`에서 nodata 칸을 제외하고 남은 칸의 가중치 합으로
나눠 보간한다. 유효 칸이 하나도 없는 표본만 실패로 남긴다.

```
4칸 모두 유효   → 수정 전과 동일한 bilinear (결과 불변)
1~3칸 유효      → 유효 칸의 가중치 합으로 재정규화
0칸 유효        → 이 표본만 실패(None)
```

**값을 지어내지 않는다.** 실측 DEM 값의 볼록결합이므로 결과는 항상 그 칸들의
최소~최대 범위 안에 있다. 반환 타입은 `list[float] | None`에서
`list[float | None] | None`으로 바뀌어 표본 단위 성공/실패를 전달한다.

### B. 표본 단위 실패 허용

새 헬퍼 `_measured_parts()`가 실측 없는 표본을 버리고 **좌표·고도·표시경로를
같은 기준으로 정렬**한다. 다음 두 조건 중 하나라도 어기면 `None`을 반환해
호출자가 경사를 미확인으로 둔다.

| 기준 | 값 | 이유 |
| --- | --- | --- |
| 최소 커버리지 | 표본의 **80% 이상** | 근거가 얇은 경사를 사실로 내보내지 않기 위해 |
| 최대 결측 간격 | 남은 이웃 표본 사이 **180m 이하** | 결측이 길면 그 사이 언덕이 통째로 사라져 평지처럼 보임 |

표본 간격은 90m이고 walking part는 `MAX_SUPPORTED_TOTAL_WALK_M=15000` 이내라
200표본×90m=17.9km 상한에 걸리지 않는다. 따라서 180m는 항상 "연속 결측 1개"를
뜻한다.

**인덱스 정합 처리.** 계획서가 "실수 나기 쉬운 지점"으로 짚은 부분이다.
버린 뒤 인덱스를 맞추는 대신 **남은 표본으로 표시경로를 처음부터 다시
생성**했다. `_anchor_subpath(compact, start, end)`를 남은 anchor 쌍으로 다시
호출하므로 경사 구간과 화면 선이 구조적으로 어긋날 수 없다. 이 변경으로
기존의 사전 생성 블록은 죽은 코드가 되어 제거했다.

### 네트워크 fallback도 같은 경로를 지난다

Open-Meteo 응답도 `_measured_parts()`를 거친다. 결측이 없으면 커버리지 100%라
동작이 달라지지 않으면서 코드 경로는 하나로 유지된다.

### 캐시

`CACHE_SCHEMA_VERSION` **4 → 5**. 기존 파일은 삭제되지 않고 무시되며, 미스가
나면 로컬 DEM 재계산이라 **외부 API 호출이 없다.** 되돌리려면 숫자를 4로
내리면 된다.

`route_feature_cache`(현재 v13)는 **건드리지 않았다.** TTL이 1,800초(30분)라
자동 만료되는 반면, 버전을 올리면 배포 직후 모든 OD가 미스가 되어
`_collect_static_featured_routes()`의 TMAP 재수집을 유발한다. 얻는 것은
"30분 일찍 반영"뿐이라 비용이 이득을 넘는다.

## 3. 계약 준수 확인

| 계약 | 처리 |
| --- | --- |
| 미확인을 0으로 대체하지 않음 | 유효 칸 0개면 표본 실패, 커버리지 미달이면 `unavailable` |
| 끊어진 part 사이를 잇지 않음 | part별 처리 유지, 기존 회귀 테스트 통과 |
| 표시용 경로 정합 | 남은 표본으로 재생성. 전 구간 단언으로 고정 |
| **결과 dict에 새 키 없음** | 프로그램으로 확인 — 추가 0개, 누락 0개 |
| 캐시 무효화 | `CACHE_SCHEMA_VERSION` 4→5 |

결과 dict 키가 그대로이므로 `ai/api/router.py`가 feature로 펼치는 항목과
`feature_snapshot_hash`의 **스키마는 바뀌지 않는다.** 해안 경로의 경사 *값*은
의도대로 달라진다.

"해안 보정을 썼다"는 정보는 계획서 지침대로 결과 dict가 아니라 로그로 남긴다.

```
90m 경사: 실측 없는 표본 %d/%d개를 제외하고 계산
```

## 4. 검증

### 4.1 수정 전 실패를 먼저 확인

계획서 6장 지침대로 **수정 전에 새 테스트가 실패하는 것을 먼저 확인**했다.

```
4 failed, 24 passed     ← 수정 전
28 passed               ← 수정 후
```

실패한 4개는 A·B가 대상으로 삼은 케이스였고, `unavailable` 유지 케이스와
전 구간 유효 회귀 테스트는 수정 전에도 통과했다.

## 6. 알려진 한계

- **바다 위·DEM 커버리지 밖 구간은 여전히 미확인이다.** 90m 지형 DEM에 실측이
  없으므로 어떤 방법으로도 실제 경사를 만들 수 없다. 이는 결함이 아니라
  의도한 동작이다.
- **교량 보도의 경사는 지형 경사가 아니다.** 영도대교처럼 수면 위를 지나는
  구간은 교량 상판 높이를 DEM이 담지 않는다. 살아난 값은 교량 양단 육지
  표본에서 나온 지형 참고값이다.
- **커버리지 80%는 경로 단위, 결측 간격은 part 단위로 판정한다.** part 하나가
  통째로 미확인이어도 다른 part가 충분하면 경로 전체는 계산된다.
