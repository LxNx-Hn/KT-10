# 작업지시서 — 해안 구간 도보 경사 미확인 문제

- 작성일: 2026-08-14
- 상태: **작업 전 계획서** (코드 변경 없음)
- 대상: `ai/features/elevation.py`
- 증상: 바다에 가까운 경로에서 도보 경사가 `unavailable`로 나옴

---

## 1. 확정된 원인

DEM 고도는 **bilinear 보간**이라 표본 하나마다 주변 픽셀 4칸을 읽는다. 그 중
**하나라도 nodata면 함수 전체가 `None`을 반환**한다.

```python
# ai/features/elevation.py:155-169
values = [ (y0,x0), (y0,x0+1), (y0+1,x0), (y0+1,x0+1) ]   # 4칸
if any(... nodata ...):
    return None          # ← 루프 밖으로 나간다
```

두 가지가 겹친다.

**① 해안 픽셀은 육지 위에 있어도 이웃이 바다다.** 격자가 90m라 해안에서 90m
안쪽이면 4칸 중 최소 하나가 바다다. 실제 보행로는 멀쩡히 육지인데 걸린다.

**② 표본 하나의 실패가 경로 전체를 버린다.** `return None`이 루프 밖으로
나가므로 1km 중 10m만 해안에 닿아도 전부 `unavailable`이 된다.

### 뒤따르는 fallback도 all-or-nothing이다

```
_regional_dem_elevations()   → 하나라도 nodata면 None
_local_dem_elevations()      → COG 타일도 masked 하나면 None (ELEVATION_DEM_DIR 필요)
network fallback             → live 기본값 ELEVATION_NETWORK_FALLBACK_ENABLED=false
⇒ _empty("unavailable")
```

### 참고 수치

번들 DEM `ai/data/precomputed/busan_dem_clipped_90m.tif`는 부산 bbox를 자른
파일이라 **nodata가 전체의 72.4%** (627×546 중 247,934칸)다. 바다뿐 아니라
부산시 경계 밖도 포함된다. 즉 해안·시계 근처 어디서나 같은 문제가 난다.

## 2. 목표와 비목표

### 목표

해안 인접 보행 구간에서 **실제 육지 위 표본은 고도를 얻어** 경사를 계산한다.

### 비목표

- 바다 위·DEM 커버리지 밖 좌표에 값을 지어내지 않는다
- 정밀도를 낮추는 대신 정확도를 속이지 않는다
- 경사 계산식, 90m 표본 간격, 표시용 경로(`display_path_parts`) 로직은 건드리지
  않는다

## 3. 선행 작업 — 규모부터 측정

고치기 전에 **지금 얼마나 실패하는지, 제안한 수정이 실제로 그걸 살리는지**를
숫자로 확인한다. 추정으로 시작하지 않는다.

1. 부산 해안 OD 표본을 정한다 (오시리아·해운대·송정·다대포·영도 등, 20~30건)
2. 각 경로의 90m 표본에 대해 다음을 집계하는 일회성 스크립트를 짠다
   - 표본 총수
   - bilinear 4칸이 모두 유효한 표본 수
   - 4칸 중 일부만 유효한 표본 수 ← **방향 A로 살릴 수 있는 것**
   - 4칸 전부 nodata인 표본 수 ← **살릴 수 없는 것 (바다 위)**
3. "일부만 유효"가 지배적이면 방향 A로 충분하다. "전부 nodata"가 많으면
   DEM 자산 자체를 손봐야 하므로 4장 대안을 재검토한다

이 측정 결과를 작업 착수 전에 공유한다.

## 4. 수정 방향

### 권장 — A. 유효한 이웃만으로 보간

`_regional_dem_elevations()`에서 4칸 중 nodata를 **제외하고** 남은 유효 칸의
가중치를 재정규화해 보간한다. 유효 칸이 하나도 없을 때만 그 표본을 실패로
처리한다.

```
4칸 모두 유효   → 지금과 동일한 bilinear
1~3칸 유효      → 유효 칸의 가중치 합으로 나눠 재정규화
0칸 유효        → 이 표본은 실패
```

**왜 정직한가**: 값을 지어내는 게 아니라 **실측 DEM 값만** 쓴다. 다만 해안에서
최대 90m 이내의 이웃 값에 기대므로 정밀도가 약간 떨어진다. 이 서비스의 지형
피처는 원래 "90m 격자 지형 수준의 참고값"이지 보도 구배가 아니므로 계약
범위 안이다.

**변경 규모**: 함수 하나, 십수 줄.

### 함께 판단할 것 — B. 표본 단위 실패 허용

A를 적용해도 일부 표본이 살아나지 않으면(진짜 바다 위, DEM 밖) 그때 검토한다.
실패한 표본만 버리고 나머지로 계산하되, 다음을 반드시 정한다.

- **최소 커버리지 비율** — 예: 표본의 80% 이상 살아야 `estimated_90m`, 아니면
  `unavailable`
- **최대 결측 간격** — 연속 결측이 길면 두 표본 사이 구간이 과도하게 넓어져
  중간 언덕을 숨긴다. 상한을 넘으면 그 part는 미확인
- **인덱스 정합** — `sampled_parts`는 part별로 잘라 쓰고
  `display_path_parts`는 `pairwise(anchors)`로 만든다. 표본을 버리면 **anchors와
  display path도 같은 기준으로 버려야** 한다. 여기가 실수 나기 쉬운 지점

B는 A보다 변경 범위가 크므로 **A만으로 부족할 때만** 진행한다.

### 기각 — C. DEM 자산 재생성

바다 칸을 최근접 육지 값으로 채우거나 clip 범위를 넓히는 방법. 코드 변경이
없다는 장점이 있으나,

- 원본 관측이 아닌 합성값이 DEM에 섞여 provenance가 흐려진다
- QGIS 재생성 절차와 `data/catalog.json` 갱신이 따라온다
- 바이너리 자산 교체라 리뷰가 어렵다

이번 작업에서는 하지 않는다. A/B로 해결되지 않는 잔여가 크면 별건으로 올린다.

### 기각 — D. 실패한 표본만 다른 소스로 메우기

COG 타일이나 Open-Meteo로 구멍을 메우는 방법. 한 경로 안에서 소스가 섞여
`elevation_source` 표기가 모호해지고, live 기본값이 network fallback 비활성이라
정책과도 어긋난다.

## 5. 반드시 지킬 계약

| 계약 | 확인 방법 |
| --- | --- |
| 미확인을 0으로 대체하지 않음 | 유효 칸 0개면 그 표본은 실패로 두고, 커버리지 기준 미달이면 `unavailable` |
| 끊어진 part 사이를 잇지 않음 | part별 처리 유지, 기존 회귀 테스트로 확인 |
| 표시용 경로 정합 | `display_path_parts`가 표본 인덱스와 어긋나지 않을 것 (B 적용 시 특히) |
| 결과 dict 키 구성 | **새 키를 추가하지 말 것** — 아래 참조 |
| 캐시 | 결과가 달라지므로 `CACHE_SCHEMA_VERSION` 증가 |

### 결과 dict에 키를 추가하면 안 되는 이유

`ai/api/router.py`가 `slope_segments`를 뺀 나머지 elevation 키를 그대로 feature에
펼치고, 스냅샷은 **언더스코어 키만** 제외한다. 따라서 `elevation_*` 계열에 새
키를 넣으면 **`feature_snapshot_hash`가 바뀌고 모델 feature schema 검증에
영향**을 준다.

"해안 보정을 썼다"는 정보를 남기고 싶다면 로그로 남기고, 결과 dict는 건드리지
않는다. 굳이 넣어야 한다면 언더스코어 키로 하고 별도 승인을 받는다.

## 6. 테스트 계획

기존 `ai/tests/test_elevation.py`에 이미 합성 DEM을 만드는 패턴이 있다
(`rasterio.transform.from_origin`, `np.arange(...)`). 실제 부산 DEM에 의존하지
않고 그 방식으로 결정적으로 검증한다.

| 테스트 | 내용 |
| --- | --- |
| 해안 인접 표본 복구 | 절반이 nodata인 합성 DEM에서, 육지 쪽 표본이 고도를 얻고 경로가 `estimated_90m`이 되는지 |
| 완전 결측은 여전히 미확인 | 4칸 모두 nodata인 좌표만으로 된 경로는 `unavailable` |
| 값의 타당성 | 유효 칸만으로 보간한 값이 그 칸들의 최소~최대 범위 안인지 (지어낸 값이 아님을 보장) |
| 기존 회귀 | 4칸 모두 유효한 경우 결과가 **수정 전과 동일**한지 |
| part 경계 | 끊어진 part 사이 가짜 상승량이 생기지 않는지 (기존 테스트 유지) |

**수정 전에 "해안 인접 표본 복구" 테스트가 실패하는 것을 먼저 확인**한 뒤
고친다.
