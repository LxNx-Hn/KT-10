# 제품 의사결정 기준

기준일: 2026-07-24 (Asia/Seoul)

이 문서는 경로 추천, AI 학습, 개인화, 결과 UI에 관한 최신 단일 기준
(SSOT)입니다. 다른 문서와 충돌하면 이 문서를 우선하고, 구현 현황은
`CURRENT_STATUS_AND_FOLLOW_UP_REPORT.md`에서 별도로 확인합니다.

## 1. 추천 문제의 정의

서비스는 경로 자체의 사실과 사용자 적합도를 분리합니다.

1. **경로 사실·특성 생성**
   - 실제 공급자 경로에서 소요시간, 도보거리, 환승, 계단·승강기·저상버스
     확인 상태, GLO-90 지형 추정, 건물 그늘 등 근거가 있는 값을 계산합니다.
   - 계산된 사실에서 `빠른 길`, `도보가 짧은 길`, `경사가 완만한 길`,
     `그늘 많은 길`, `환승이 단순한 길`, `계단 없는 길` 같은 특성 배지를
     만듭니다.
   - 확인되지 않은 값은 `null`/`unknown`으로 유지합니다. 0이나
     `없음`으로 바꾸거나 LLM이 추정해 채우지 않습니다.
2. **프로필·조건 적합도 산정**
   - 같은 경로 사실을 6개 기본 프로필, 이번 이동 조건, 로그인 사용자의
     장기 이동지원 설정과 매칭합니다.
   - 경로를 적합 점수순으로 정렬하며 순위를 주 결과로 표시합니다.
   - 특성 배지는 경로를 설명하는 사실이고, 특정 배지를 보존하기 위해
     점수순 정렬을 임의로 뒤집지 않습니다.

## 2. 프로필과 조건

기본 프로필은 다음 6개로 확정합니다.

| ID | 표시명 |
| --- | --- |
| `general` | 일반 |
| `elderly` | 고령자 |
| `child` | 아동 |
| `youth` | 청소년 |
| `disabled` | 장애인 |
| `pregnant` | 임산부 |

기본 프로필은 개인의 모든 이동능력을 단정하는 진단값이 아닙니다. 특히
`disabled` 하나로 접근성 요구를 추정하지 않고, 장기 이동지원 설정과 이번
이동 조건을 함께 사용합니다.

이번 이동에만 적용하는 빠른 조건은 기본 프로필과 분리합니다.

- 짐 많음
- 유아차
- 계단 회피
- 그늘 우선
- 저상버스 우선
- 환승 최소

휠체어, 보행보조기, 계단 회피 필수, 최대 도보거리, 시각·청각 안내 필요와
같은 장기 요구는 로그인 프로필에 저장합니다. 확인된 필수조건 위반은
감점이 아니라 제외 사유가 될 수 있지만, 데이터가 미확인인 경우에는
제외하지 않고 `확인 필요`로 표시합니다.

## 3. 점수와 설명

- 카드의 가장 큰 정보는 `1순위`, `2순위` 같은 순위입니다.
- 점수는 `베이스라인 적합 점수`라는 이름으로 보조 표시할 수 있습니다.
- 점수는 안전도, 접근 가능 확률, 사고 확률 또는 목적지 도착 확률이
  아닙니다. UI에 이 한계를 명시합니다.
- 소요시간, 도보거리, 환승, 경사, 그늘, 시설 확인 상태와 추천 이유를
  점수 근거로 함께 제공합니다.
- 모델의 SHAP 값이나 LLM 설명을 인과관계 또는 검증된 안전 근거라고
  표현하지 않습니다.

## 4. AI 평가 베이스라인과 운영 모델

LLM/Codex judge로 초기 경로를 평가하고 학습하는 것은 실제 사용자 라벨이
적은 단계의 베이스라인으로 허용합니다. 평가 입력은 공급자 이름과 기존
순위를 가린 동결된 경로 사실이어야 하며, 점수와 판단 근거, 미확인 항목,
프롬프트·루브릭 버전을 함께 보존합니다.

모델 출처는 다음처럼 분리합니다.

| 산출물 | 의미 | 운영 자동 승격 |
| --- | --- | --- |
| `rankers.judge-baseline.pkl` | LLM/Codex judge 라벨 기반 베이스라인 | 금지 |
| `rankers.human-candidate.pkl` | 실제 사용자·전문가 라벨 기반 후보 | 금지 |
| `rankers.pkl` | 관리자가 검토·승인한 운영 모델 | 해당 |

Judge 베이스라인은 기술 데모와 초기 비교 기준으로 유용하지만
`실사용자 검증 모델`로 부르지 않습니다. 실제 사용자 라벨이 쌓이면 별도
holdout에서 규칙 기준, judge 베이스라인, 사람 라벨 후보를 비교한 뒤
관리자가 운영 승격을 결정합니다.

## 5. 개인화

- 로그인 사용자의 후기 저장 직후 사용자별 온라인 상태를 갱신합니다.
- 초기 5건까지는 베이스라인을 우선하며, 개인화 영향은 최대 35%입니다.
- 게스트 후기는 개인화 상태나 전역 학습에 사용하지 않습니다.
- 전역 재학습은 명시적으로 동의한 후기만 익명화·품질검토 후 사용합니다.
- 전역 후보 생성과 운영 모델 승격은 관리자가 수동으로 수행하며, 새 모델이
  운영 파일을 자동 덮어쓰지 않습니다.

## 6. 결과 화면

- 모바일 결과는 지도 중심 화면과 한 장씩 보이는 수평 경로 카드로
  구성합니다.
- 카드 스와이프, 이전/다음 버튼, 키보드 조작을 모두 지원합니다.
- 선택 카드가 바뀌면 지도에서 해당 경로와 그늘 오버레이가 즉시
  활성화되고, 지도에서 경로를 선택하면 해당 카드로 이동합니다.
- 카드에는 순위, 베이스라인 적합 점수, 핵심 지표와 사실 배지를 먼저
  표시하고 상세 근거·주의사항은 펼쳐서 확인합니다.
- 스와이프만을 유일한 조작 수단으로 만들지 않습니다.

## 7. 사실성 경계

- GLO-90 결과는 약 90m 격자의 지형 추정이며 보도 자체의 실측 구배가
  아닙니다.
- 현재 그늘 계산 범위는 건물 그늘뿐입니다. 나무 그늘과 지형 그림자는
  포함하지 않습니다.
- 합성 건물은 기능 데모, VWorld 결과는 공공 건물 기반 추정으로 구분합니다.
- 건물 높이가 없거나 0인 값은 0m 건물로 해석하지 않습니다.
- 공급자 실패, 빈 geometry, 미확인 시설을 직선·0분·0개·그늘 0%로
  자동 대체하지 않습니다.

## 8. 완료 기준

배포 가능한 데모는 다음을 모두 충족해야 합니다.

1. 6개 프로필과 6개 상황 조건이 전 계층에서 같은 계약을 사용합니다.
2. 실제 또는 명시된 데모 경로의 사실·특성과 적합 점수를 분리해 제공합니다.
3. 지도와 스와이프 카드가 같은 선택 상태를 공유합니다.
4. Judge 베이스라인의 출처·버전·검증 지표가 모델과 함께 기록됩니다.
5. AI, 백엔드, 프론트 테스트와 생산 빌드, Docker 실행 검증이 통과합니다.
6. 외부 키가 필요한 실데이터는 실제 호출로 검증하며 실패 시 데모로
   무단 전환하지 않습니다.
