# 제품·검증 계획

기준일: 2026-07-24 (Asia/Seoul)

결정의 원문은 `PRODUCT_DECISIONS.md`, 현재 증거와 차단사항은
`CURRENT_STATUS_AND_FOLLOW_UP_REPORT.md`를 기준으로 합니다.

## 확정 방향

- 서비스: 교통약자 및 이동취약자 맞춤형 보행·대중교통 경로 추천 PWA
- 범위: 부산 전역, 초기 검증은 평지·급경사·버스·도시철도·환승 유형을
  포함한 층화 OD
- 지도: Kakao Maps 배경지도와 경로·건물 그늘 오버레이
- 후보: ODsay 대중교통 + TMAP/OSMnx 보행 geometry
- 1단계 AI: 경로 사실을 구조화하고 사실 기반 특성 배지를 생성
- 2단계 AI: 프로필·상황·개인 설정의 적합 점수를 계산해 순위화
- 기본 프로필: 일반·고령자·아동·청소년·장애인·임산부 6개
- 상황 조건: 짐 많음·유아차·계단 회피·그늘 우선·저상버스 우선·환승
  최소 6개
- 결과 UI: 순위를 크게, `베이스라인 적합 점수`를 보조로 표시하고 지도와
  동기화된 수평 스와이프 카드 제공
- 개인화: 로그인 사용자의 명시적 후기만 즉시 반영, 첫 5건 베이스라인
  우선, 개인 영향 최대 35%
- 전역 학습: 동의 후기만 검토·가공하고 관리자가 후보 생성과 운영 승격을
  수동 수행
- 사고정보: 현재 서비스·모델에서 제외

## 모델 단계

### A. 설명 가능한 규칙 베이스라인

경로 사실에서 특성 배지와 초기 적합도를 계산합니다. 모델이 없어도
서비스가 실패하지 않고 추천 이유를 설명하는 기준입니다.

### B. LLM/Codex judge 베이스라인

동결된 경로 사실을 공급자명·기존 순위를 가린 상태로 평가합니다. 6개
프로필과 상황 조합별 0~4 relevance, 후보쌍 선호, 근거와 미확인 항목을
수집합니다. 루브릭·프롬프트·모델 버전과 배치 해시를 보존하고
`rankers.judge-baseline.pkl`로 분리합니다.

### C. 사람 라벨 후보

실제 사용자·전문가가 같은 동결 후보를 평가합니다. 초기 목표는 기존
9인 절차를 유지하되, 사람 수가 적은 단계에서도 judge 베이스라인과
분리된 비교 자료로 보존합니다. 결과는 `rankers.human-candidate.pkl`이며
자동 운영 승격하지 않습니다.

### D. 승인 운영 모델

OD 그룹 holdout의 NDCG@3, 후보쌍 정확도, 프로필별 실패 사례와 규칙·judge
기준 대비 결과를 관리자가 검토합니다. 승인된 파일만 `rankers.pkl`로
승격합니다.

## 실행 우선순위

### P0. 계약 통일

1. FE·BE·AI의 프로필을 6개로 통일
2. 6개 상황 조건의 요청·응답·저장 계약 추가
3. 경로 사실·특성·적합도·모델 provenance 스키마 고정
4. 점수의 비안전·비확률 설명과 필수조건/미확인 처리 고정

### P1. 결과 UI

1. 세로 목록을 지도 동기화 수평 카드로 변경
2. 순위, 베이스라인 적합 점수, 핵심 지표·사실 배지를 카드 요약에 표시
3. 스와이프·버튼·키보드·스크린리더 조작 지원
4. 카드 선택과 경로·그늘 오버레이 선택을 양방향 동기화

### P2. 실제 후보와 피처

1. ODsay Server 허용 IP에 개발 공인 IPv4 `119.202.222.84` 등록
2. ODsay `searchPubTransPathT`·`loadLane` 라이브 smoke 통과
3. 부산의 평지·급경사·해안·버스·도시철도·환승 중심 OD를 층화
4. 경로 geometry, GLO-90 지형과 건물 그늘 피처 스냅샷 동결
5. 미확인과 0을 구분하고 공급자·품질·시간 메타데이터 보존

### P3. Judge 베이스라인 학습

1. 프로필·상황별 블라인드 평가 루브릭 확정
2. 순서를 바꾼 반복 평가와 일관성 검사
3. 경로 사실과 라벨 ID 정합성 검사
4. OD 단위 train/validation 분리
5. 프로필별 XGBRanker와 메타데이터 생성
6. 규칙 기준 대비 오프라인 보고서 작성

### P4. 사람 검증과 개인화

1. 실제 사용자·전문가 라벨을 judge 라벨과 분리 수집
2. 모델 간 동일 holdout 비교
3. 실제 후기의 사용자별 즉시 갱신과 최대 35% 제한 검증
4. 동의 후기만 익명화해 전역 후보를 수동 생성
5. 관리자가 성능·안전 경계를 검토하고 운영 승격

### P5. 실데이터·배포

1. Kakao Local/OAuth, VWorld, OpenWeather 키와 운영 도메인 설정
2. 운영 서버 고정 egress IP를 ODsay에 추가
3. VWorld 좌표계·높이 단위·결측률 표본 검증
4. 현장 표본으로 시간대별 건물 그늘 오차 검증
5. 전체 테스트, 생산 빌드, Docker health와 실제 공급자 E2E 통과
6. 작업 단위별 커밋, 원격 CI 통과 후 배포

## 완료 기준

- 경로의 사실·특성과 사용자 적합도가 API·모델·UI에서 분리됩니다.
- 6개 프로필과 6개 상황 조건이 전 계층에서 동일하게 동작합니다.
- 경로가 적합 점수순으로 표시되고 특성 배지가 순서를 임의로 바꾸지
  않습니다.
- 지도와 카드가 스와이프·클릭·키보드에서 같은 선택 상태를 유지합니다.
- GLO-90, 건물 전용 그늘, 미확인 값의 사실성 한계가 표시됩니다.
- Judge 베이스라인과 사람/운영 모델의 파일·메타데이터·평가 결과가
  분리됩니다.
- 외부 키가 필요한 기능은 실제 호출로 검증되며 실패를 0이나 데모로
  숨기지 않습니다.
- 개인화는 5건/35% 제한을 지키고 운영 모델은 관리자가 수동 승격합니다.
