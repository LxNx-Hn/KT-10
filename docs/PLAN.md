# 제품·검증 계획

기준일: 2026-07-25 (Asia/Seoul)

결정의 원문은 `PRODUCT_DECISIONS.md`, 현재 증거와 차단사항은
`CURRENT_STATUS_AND_FOLLOW_UP_REPORT.md`를 기준으로 합니다.

## 확정 방향

- 서비스: 교통약자 및 이동취약자 맞춤형 보행·대중교통 경로 추천 PWA
- 범위: 부산 전역, 초기 검증은 평지·급경사·해안·버스·도시철도·환승을
  포함한 층화 OD
- 지도: Kakao Maps 배경지도와 경로·시간별 건물 그늘 오버레이
- 후보: ODsay 대중교통, TMAP 보행 후보, 명시적 opt-in OSMnx 보행
  geometry 복구
- 1단계: 실제 경로 사실을 동결하고 결정적 규칙으로 특성 라벨 생성
- 2단계: 프로필·상황·개인 설정의 상대 적합도를 계산해 점수순 순위화
- 기본 프로필: 일반·고령자·아동·청소년·장애인·임산부 6개
- 상황 조건: 짐 많음·유아차·계단 회피·그늘 우선·저상버스 우선·환승
  최소 6개
- 결과 UI: 순위를 크게, 상대 적합 점수를 보조로 표시하고 지도와
  동기화된 한 장씩 보이는 수평 카드 제공
- 개인화: 로그인 사용자의 명시적 후기만 즉시 반영, 첫 5건 베이스라인
  우선, 개인 영향 최대 35%
- 전역 학습: 동의 후기만 검토·가공하고 관리자가 후보 생성과 운영 승격을
  수동 수행
- 그늘 범위: 건물 그늘만 포함, 나무·지형 그림자는 미추정
- 사고정보: 현재 서비스·모델에서 제외

## 모델 단계

### A. 설명 가능한 규칙 베이스라인

실제 경로 사실에서 `제일 빠른 길`, `경사가 완만한 길`,
`그늘 많은 길` 등의 특성 라벨과 초기 적합도를 계산합니다. 승인 모델이
없어도 `ROUTE_MODE=live`가 동작하는 서비스 기준입니다.

### B. 초기 프로필 평가 베이스라인

동결된 실제 경로 피처를 공급자명·기존 순위에 의존하지 않고 평가합니다.
6개 프로필별 0~4 relevance, 근거와 미확인 항목, 실제 평가 시각,
루브릭·프롬프트·모델 버전을 보존합니다.

결과는 `rankers.bootstrap-baseline.zip`이며 실사용자 검증으로 표현하거나
운영으로 자동 승격하지 않습니다. 부산 380 OD·실제 후보 1,137개·6개
프로필 평가 6,822개로 학습했고, 프로필별 304 OD 학습·76 OD 검증을
완료했습니다. 사람 평가 후보와 승인 운영 모델은 아직 없습니다.

### C. 사람 라벨 후보

실제 사용자·전문가가 같은 동결 후보를 평가합니다. 6개 프로필의 각
후보에 최소 9명 평가가 있어야 하며, 스냅샷 해시와 동일 OD holdout을
검증합니다. 결과는 `rankers.human-candidate.zip`입니다.

### D. 동의 후기 혼합 후보

명시적으로 동의한 실제 후기만 익명화하고 사람이 정한 50% 미만의 비중으로
초기 사람 라벨에 결합합니다. 결과는
`rankers.review-mixed-candidate.zip`이며 `human_reviewers` 전용 승격
절차를 통과할 수 없습니다.

### E. 승인 운영 모델

OD holdout의 NDCG@3, 후보쌍 정확도, 프로필별 실패 사례와 규칙·judge
기준 대비 결과를 관리자가 검토합니다. 검토한
`rankers.human-candidate.zip`의 SHA-256, 승인자와 승인 근거를 명시한
수동 절차만 `rankers.human-validated.zip`을 생성합니다.

모든 파일은 checksum manifest와 프로필별 XGBoost JSON을 담은
비실행형 ZIP 아카이브입니다. pickle 모델을 로드하지 않습니다.

## 구현 완료 후 동결할 계약

현재 작업본에 구현되었고 최종 전체 회귀검증이 남은 범위입니다.

1. FE·BE·AI의 6개 프로필과 6개 상황 조건
2. 경로 사실·특성 라벨과 프로필·조건 적합도 분리
3. 미확인을 0 또는 없음으로 바꾸지 않는 점수·UI
4. 점수순 수평 카드와 지도 경로·그늘 선택의 양방향 동기화
5. 스와이프·버튼·키보드·스크린리더 대체 조작
6. 실제 후보 수집→건물 그늘→enriched snapshot→규칙/모델 순위의 정식
   백엔드 흐름
7. `captured_at`과 `shade_evaluated_at`, query group과 동일 방향 OD
   holdout의 분리
8. 라벨링 배치 API의 `LABELING_API_TOKEN` 보호
9. 사용자별 온라인 개인화와 동일 impression 중복 후기 방지
10. 모델 tier, 라벨 출처, checksum 기반 관리자 승격

AI 서버의 직접 `POST /recommend`는 409를 반환하는 비활성 호환
endpoint입니다. 초기 배치의 외부 진입점은 백엔드
`POST /api/routes/labeling-candidates`입니다.

## 남은 실행 순서

### P0. 외부 공급자 해제

1. 완료: ODsay 개발 Server 허용 IP 등록과
   `searchPubTransPathT`·`loadLane` 라이브 smoke
2. 완료: Kakao JavaScript Places의 `북구청`·`부산역` 브라우저 E2E
3. 남음: Kakao REST/OAuth, VWorld, OpenWeather 키와 콘솔 도메인 설정
4. 남음: TMAP 키 또는 운영에서 허용할 OSMnx로 실제 보행 geometry 확보
5. 남음: 운영 HTTPS origin과 고정 egress IP 확정·등록

### P1. 실제 후보 스냅샷

1. 부산의 평지·급경사·해안·버스·도시철도·환승 중심 OD 층화
2. 32자 이상의 `LABELING_API_TOKEN`으로 보호된 백엔드 배치 실행
3. 확인된 실제 보행 geometry 구간에만 부산 QGIS 90m DEM 지형·공간·건물 그늘
   피처를 계산하고 스냅샷 동결
4. 수집시각과 그늘 평가시각, 공급자·품질·미확인 값을 보존
5. VWorld 높이 단위·결측률과 현장 그늘 오차 표본 검증

### P2. 프로필 평가 또는 사람 베이스라인

1. 평가 기준·실행 ID·루브릭 해시 확정 — 완료
2. `bootstrap-evaluation-label-v1` 해시·완전성 검사 —
   실제 후보 1,137개·6개 프로필·6,822개 완료
3. 또는 최소 9명 사람 평가로 6개 프로필 라벨 행렬 완성
4. 동일 방향 OD holdout 검증 — 프로필별 304 OD 학습·76 OD 검증 완료
5. 프로필별 오프라인 평가 보고서 작성 — metadata 기술 지표 완료,
   사람 검증 보고서는 대기

### P3. 운영 승인

1. 후보 ZIP과 SHA-256, 데이터 계보, 지표 검토
2. 사람 전용 후보만 수동으로 `rankers.human-validated.zip` 승격
3. `ROUTE_MODE=ai`, `RANKER_TIER=human_validated` 배포 smoke
4. 동의 후기 후보는 별도 비교 후 재라벨링 또는 별도 승인정책 결정

### P4. 최종 검증·배포

1. AI·백엔드 pytest, 프론트 Vitest와 production PWA build
2. Python compileall, Alembic, `git diff --check`, npm audit
3. AI·백엔드·프론트 production Docker build와 health
4. 실제 브라우저 모바일·접근성·카드↔지도 동기화 검증
5. 유효 키를 사용한 배포 E2E
6. 작업 단위별 커밋, 푸시와 원격 CI 통과

## 완료 기준

- 경로 사실·특성과 사용자 적합도가 API·모델·UI에서 분리됩니다.
- 6개 프로필과 6개 상황 조건이 전 계층에서 동일하게 동작합니다.
- 경로가 적합 점수순으로 표시되고 특성 라벨이 순서를 바꾸지 않습니다.
- 지도와 카드가 스와이프·클릭·키보드에서 같은 선택 상태를 유지합니다.
- 부산 QGIS 90m DEM, 건물 전용 그늘, 미확인 값의 사실성 한계가 표시됩니다.
- `captured_at`과 `shade_evaluated_at`을 혼동하지 않습니다.
- Judge·사람·후기혼합·승인 운영 모델의 파일과 출처가 분리됩니다.
- 외부 키가 필요한 기능은 실제 호출로 검증되며 실패를 0이나 데모로
  숨기지 않습니다.
- 개인화는 5건/35% 제한을 지키고 운영 모델은 관리자가 수동 승격합니다.
- 전체 로컬 검증과 원격 CI가 모두 통과합니다.
